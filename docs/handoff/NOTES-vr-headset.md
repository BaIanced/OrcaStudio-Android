# VR port: headset recipes and results

Read the section the backlog item names, not the whole file. Paths are under `android/app/src/main/java/app/orcaandroid/` unless they start with `android/`.


## On-headset recipe, nobody wearing it
`dumpsys vrpowermanager` said `HEADSET_MOUNTED` with `Virtual proximity state: CLOSE` while nobody wore it (2026-11-05), so it is no evidence of a wearer: ask. Controller tracking: `dumpsys OVRRemoteService` ("tracking in 6dof") and `no valid pose` in logcat; filter serials out of both.
`MSYS_NO_PATHCONV=1` in Git Bash, or `/sdcard` paths get rewritten.
1. Before: `input keyevent KEYCODE_WAKEUP`, `setprop debug.oculus.guardian_pause 1`. Proximity (user, 2026-11-06, for every headless run): read `metavr device proximity --status`; if it says overridden, do nothing; if not, turn it on with `metavr device proximity --disable` (off to on not yet run; it was already on when tried).
2. `am force-stop`, `logcat -c`, `am start`. Without the pause the Guardian dialog stopped the session after about 3 s (one run, likely cause), and a launch made while it is open starts no session.
3. Read `VrApi` lines **by the app's pid**; pid-less FPS lines can be the shell's. Tag `OrcaXr`, `VR_FPS`.
4. After: `am force-stop`. Leave Guardian paused (user wants it off, 2026-11-05). Skip `automation_disable` unless the user asks: it is what the last run ended with before the dialog came back (cause not confirmed; the pause was also cleared in that step).

## Heavier-model recipe
Model: `src-orca/resources/handy_models/OrcaSliced.3mf`. Push it to `/sdcard/Android/data/<package>/files/heavy.3mf` (`mkdir -p` first; `projectExtra` allows this directory), follow the recipe below with `--es project <that path>`, wait 60 s for the load, read `VR_SCENE`, `VR_FPS` and `VrApi` by pid. `.quest` is not debuggable, so `run-as` fails. The transport id can change mid-run, so look it up first. Use a `D:/` path for the model on the host: with `MSYS_NO_PATHCONV=1`, `/d/...` fails. Before launching, check `dumpsys activity activities` for ` ResumedActivity`: if it is `GuardianDialogActivity`, nothing starts (seen 2026-11-05: `Timeout while requesting window placement`, no process). If the pid is empty, ignore the `VrApi` lines, they are the shell's. Of five tries, the first four gave nothing (adb lost, no model, the dialog twice, the last after wake and `prox_close` with no pause). `heavy.3mf` is on the Quest.

## M1 on the headset (CI r530, Quest 3, OS v210, 2026-11-05)
- Empty bed: `XR_SESSION_STATE_FOCUSED`, `VR_SRGB write control present, encoding off`, `VR_MSAA samples 4`, swapchain 1680x1760 format 0x8c43. 120 fps (compositor 120/120, 0 stale, app about 0.75 ms).
- Sample cube: `VR_SCENE project true plates 1 active 0 vertices 36`, 118-120 fps for 30 s, no errors or crash. User saw the cube and says the bed stays in place. The runtime ran at 120 Hz here, where M0 ran at 72 (cause not checked).
- The screencap shows raw per-eye images, each rotated and offset. System panels also show large offsets between the eyes, so don't judge stereo from pixel differences; ask the wearer.
- A fresh `.quest` install has no printer: VR logs `VR_SCENE no printer installed` and leaves in about 1 s. Pick a printer in its 2D app first.
- Saving for VR: closing the panel with its X left no session (one run, not confirmed why). Back key doesn't stop the panel. What worked: start `VrActivity` over the 2D app (VR leaves at once, `the 2D app owns the engine`), wait 8 s, force-stop, start `VrActivity` again.
- `adb input tap` at `uiautomator dump` bounds works on the panel. Address the Quest by `adb -t <transport_id>`.
- With a wearer the Guardian pause is not needed. Without one and without the pause, a "Finding position in room" dialog covers everything.

## Meta tools (Muse Task 19, `MUSE-RESEARCH-0019.md`, PR #75; checked 2026-11-06, nothing installed or run)
Checked against Meta's repos: `meta-quest/agentic-tools` is Apache-2.0, its `metavr` CLI lists `app`, `files`, `capture`, `log`, `docs`, `perf`, `skills`, `telemetry`, `tapedeck`, and `perf capture`, `context`, `analyze-trace` and `gpu-counters` exist. 36 skills, including the four the report names. In `meta-quest/Meta-OpenXR-SDK`, code search finds 8 files with the GLES binding and 0 with a Vulkan one, and the seven named samples exist. SDK licence is the Oculus SDK License (`LICENSE.txt`), so read it before copying sample code into this public repo. Second review (94a14b8, 2026-11-06), checked: frontmatter sizes (2,434 bytes for the four skills, 18,582 for all 36, without the `---` lines), the "Loads automatically" text in `hz-quest-verify-first` (its description only; whether Claude Code honours it is untested). Meta's Essential policy (Feb 5 2025) lists machine, signed-user and project identifiers, system configuration, usage frequency, errors and crashes, security data, and "playtesting and debugging data" from a headset in developer mode. Not checked: the other Meta doc pages.
`metavr device` has `wake`, `proximity --disable`, `boundary --disable`, `controllers`, and `set-property` with `--set-proximity-close`, `--disable-guardian`, `--disable-dialogs` (`docs/metavr-cli.md`, HEAD 3a8553d). The report's action 6 said otherwise; Muse fixed it at 251caf4 (now action 4) and PR #75 merged 2026-11-06. So it could replace most of the on-headset recipe (untested). `boundary --disable` is `debug.oculus.guardian_pause`: tested 2026-11-06 on r533, prop 0 gave "Guardian: enabled", `--disable` put the prop back to 1 and status to "disabled (paused)". `device wake` sent the signal and `device proximity --disable` verified "overridden" (it was already). Use these instead of the raw recipe steps 1 (untested through a launch). Debug launch `--ez plateInFront true` (`claude/vr-m2`) places the plate in front of the head at the first frame. `set-property --pin` defaults to `HZDB_MQST_PIN`, then 1234, so don't run it logged in without asking the user.
Tried `npx -y metavr@1.10.0`, read-only plus a Perfetto capture, Quest 3 with r533 running, nobody asked whether it was worn, 2026-11-06. The app kept running. Set `HZDB_DEVICE` to the Quest and keep it out of output, because other Android devices are attached and `device controllers` prints controller serials. About 3 s per call; filter `npm notice` lines.
- Worked: `telemetry disable` (status "Essential only"), `device boundary --status`, `device proximity --status`, `device controllers` (status, battery, tracking), `log`, `adb logcat --pid`. Not run: `wake`, `proximity --disable`, `boundary --disable`, `set-property`.
- `perf capture --app <pkg> --duration 5000 -o <name>`: `--duration` is in ms (5 gave a 5 ms trace). A bare name lands in `%APPDATA%/odh/traces`, an absolute path gets `.pftrace` added. 10.3 MiB.
- `perf analyze-trace <file> --app <pkg>`: 2 KB summary, the app's frame count not found without `--app` (exit 1). It gave threads (`OrcaXrRender` 17 % running) and app GPU time (1.96 ms avg, 15 samples), but FPS and frame time "n/a", "no per-frame intervals", and no colour passes on this GLES app. So it doesn't replace `VR_FPS` and `VrApi` lines yet; `-m gpu` not tried. `-m vr` gave the same summary (still no frame timing, GPU 1.95 ms avg, 10.3 MiB for 5 s), but after `perf load <path>` the SQL in `perf query <path> "<sql>"` reads what the summary misses: counter `FPS` (600 samples, avg 120, max 121), `stale_frames_per_second` (15 samples, avg 1, max 2), `Stale` (601 samples, avg and max 4, meaning not checked), and slices such as `xrWaitSwapchainImage` (1200 in 5 s, avg 2 us). Join `counter` to `counter_track` for counters; output is JSON. The first run downloaded Perfetto Trace Processor to `%APPDATA%/metavr/tools/perfetto`.
- `perf context` is a 4 KB prompt for an agent, not a summary of the trace as the report says.
- `log -t TAG -n N` applies `-n` first, so `-n 5` printed nothing and `-n 3000` printed only 3 lines because of `no valid pose` spam. `adb logcat` has no `-s`. For a tag, plain `adb logcat -d -s` is still better.
- npm lists the licence as "Meta Platform Technologies SDK License", though the repo says Apache-2.0.
Traps (read from the docs, untested):
- `tapedeck bundle-apk` re-signs with `--signing-key` or a cached debug key, so its APK should not install over `.quest` without an uninstall, and uninstalling wipes the session. Back up the session or use another package first.
- `tapedeck verify-apk`'s help says "once that ships" of `bundle-apk`, and `--skip-build` mentions a `buck2` build and an embedded layer, so it may not work from the public binary.
- `metavr init` also configures the MCP server and installs skills. Use the CLI alone first (`npx -y`), and measure before adding the MCP tool schemas.
- Essential telemetry stays on after `metavr telemetry disable`, so trying it is the user's call.
OVR Metrics CSV: open, low priority. ENABLE_CSV broadcast wrote no file on Quest 3 v210; no receiver in `dumpsys package`. `VrApi` logcat lines by app pid are the working substitute. | Claude, CI r528, 2026-11-05
