## Plate placement (user design 2026-11-05; built on `claude/vr-placement`, nothing run on a headset)
User: aim at the plate, press the "second inner button" to grab (taken as the grip, not confirmed), stick up is farther, down is closer, left and right is zoom, like Virtual Desktop's screen controls (which they rate above Meta's window management). Rule (user, 2026-11-05): everything must work fine with one controller, because the user often has only one (they don't game on the Quest), but a second controller must not be useless. So one controller is the floor and a second only adds: no feature may require two, and two-controller gestures are welcome as extras. This replaces the earlier "two-handed scale is a no-go" here and `NOTES-vr-archive.md:96,161`. The same goes for hands: two-hand gestures are fine under hand tracking, though one hand "might be a better optimum". Optimise for no controller later. Smoothing is to be tuned by testing in a dev panel. Virtual Desktop's controls were not looked up; the user is unsure how they translate to a horizontal plate.
Scale verdict (user, 2026-11-06, after using r534): 1:1 looks fine but seems too small to work at, so they zoomed; they have never worked at forced 1:1, so it's hard to judge. Useful as a quick reference, especially with passthrough (their screenshot has the plate lined up on their real printer's bed). So 1:1 is not assumed to be the working scale, though it stays the default for now.
Built, Claude's choices marked for the user to overrule:
- `PlateGrab` (pure, tested): the held point rides the aim ray at a fixed distance, so pushing away while aiming down also lowers the plate (Claude's choice, the first thing to judge on the headset). Plate stays level, no yaw (choice). Hold to carry; `grabToggle` gives click on, click off, because "click" was ambiguous (default hold is a choice).
- Stick: dead zone, curve, smoothing, multiplicative rates, and axis lock so pushing away doesn't zoom (choice). Zoom is about the held point and stops at 1:1 until the stick recentres; stick click returns to 1:1 (both choices, since a zoomed model isn't true size). Limits 0.2-6 m, zoom 0.1-8.
- Hand smoothing: One Euro filter on the position. No inertia on release.
- `RayOverlay`: grey idle, cyan on the plate, orange holding. No haptics.
- Saved to prefs `vr_placement` on release, relative to the LOCAL origin (head at launch). `--ez resetPlacement true` brings a lost plate back. Logcat: `VR_INPUT`, `VR_PLACE`, `VR_TUNE`.
- Tuning: push JSON to `/sdcard/Android/data/<package>/files/vr_tuning.json`, re-read within 1 s. Fields: `minCutoffHz`, `beta`, `stickDeadZone`, `stickSmoothMs`, `stickCurve`, `distanceRate`, `zoomRate`, `axisLock`, `grabToggle`. All defaults are guesses.
- Bindings: only `oculus/touch_controller`, assumed to cover Touch Plus by compatibility mode (untested). If setup fails, VR still runs with a fixed plate.

## M1 as built
Goal: static world-locked plate plus a real model, 1:1, head-tracked. Shadows and selection outline off. Acceptance: JVM tests pass, 2D unchanged, 72 fps on the baseline plate, 2-minute user check.
- **View source:** `ViewSource` (`render/Camera.kt`), implemented by `Camera` and `VrActivity.EyeView`. `PlateRenderer.viewSource` replaces its `camera.eye()` / `camera.pxSize` calls.
- **VR entry:** `PlateRenderer.drawEye(fbo, w, h, viewProjection, source)`, bypassing `drawFrame` and its supersampler, accumulator and loupe.
- **Target framebuffer, deviation from the design:** no `targetFbo` on the four effect classes. Nothing on the VR path binds framebuffer 0: `Accumulator`, `Supersampler` and the loupe are bypassed, and `SceneEffects` and `SelectionOverlay` only run with shadows on or a selection, both off in M1. Add it when a milestone turns either on (M3 selection at the latest), or the pass lands on framebuffer 0.
- **World transform:** `VrMath.plateToLocal`: (x, y, z) mm to 0.001 * (x, z, -y), active plate centre 0.4 m below and 0.6 m ahead of the LOCAL origin (`TABLE_Y`, `TABLE_AHEAD`, for the user check). VP = P * V * W. `localToPlate` gives the shaders' eye in mm.
- **Eye target (shim):** one FBO per swapchain image, one depth renderbuffer per eye, depth invalidated on release. `nativeAcquireImage` now returns the FBO.
- **sRGB trap (untested):** the swapchain picks `GL_SRGB8_ALPHA8` first and the app's shaders write display-encoded colour, so the shim disables `GL_FRAMEBUFFER_SRGB_EXT` when `GL_EXT_sRGB_write_control` is listed. Logcat: `VR_SRGB`.
- **Antialiasing (untested):** 4x `GL_EXT_multisampled_render_to_texture`, single sample if absent. Logcat: `VR_MSAA`.
- **Scene load:** `VrActivity.loadScene`, same order as `ui/AppViewModel.kt:85-98`: prepare, init, `loadPresets`, select last printer, `loadProject`, select the project's printer, `scene()`. The 2D sets mesh and bed in `ui/components/Viewport.kt:741,761`. Project: `--es project <path>` inside the app's storage, else `filesDir/session/session.3mf`. Logcat: `VR_SCENE`. Colours come from the project; surface materials stay basic.
- **2D and VR share one engine:** `Engine.initialized` makes VR leave if the 2D app is already up in the process, so it never loads over the 2D scene. The reverse (opening 2D while VR runs) is not guarded. M2 must settle both, so force-stop first when testing M1.
